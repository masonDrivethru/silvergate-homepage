화면 비교 모듈 테스트

같은 가상 SOP 문서(v3 → v4)를 일반 HTML(JSP 방식), Vue 3, React로 각각 그린 뒤 같은 모듈로 비교합니다. 왼쪽·오른쪽 화면은 원래 그려진 그대로 두고, 바뀐 곳에만 색을 입힙니다.

추가 (초록) 수정 (파란 밑줄) 삭제 (빨간 취소선) 반대쪽 빈 칸

서버가 그린 완성된 HTML 페이지 두 장을 그대로 띄워 비교합니다. 실제 JSP에서는 left: { url: '/sop/view.jsp?ver=3' } 처럼 주소만 넘기면 됩니다. 위쪽에서 한 장 보기를 누르면 삭제된 내용까지 한 문서에 겹쳐 보입니다.

Vue 3 컴포넌트가 그린 화면입니다. 모듈은 Vue를 모르고 그려진 결과만 봅니다. 새 버전을 고치면 Vue가 다시 그리고, 비교도 자동으로 다시 합니다.

React 18 컴포넌트가 그린 화면입니다. 표시는 화면 구조를 바꾸지 않으므로 React가 다시 그려도 충돌하지 않습니다.

표 구조가 바뀌는 경우들입니다. 칸 병합(colspan·rowspan), 열 추가, 줄 순서 바뀜, 구조 전체 변경을 각각 비교합니다. 맨 위는 머리글 2단과 설비별 묶음 칸이 섞인 실제 결과표 모양입니다.

서버에서 받은 JSON 데이터로 표를 그리는 바닐라 JS 컴포넌트입니다. 기준정보가 하나 늘면 블록(줄)이 하나 쌓이고, 조건에 맞으면 칸을 합치고, 실행 데이터(회차) 수만큼 표를 반복해서 그립니다. 컴포넌트는 비교 모듈을 전혀 모르고(고유 ID 도 달지 않음) 부를 때마다 통째로 새로 그립니다. 새 버전에는 블록 추가, 기준 수정, 가운데 끼어든 회차 표, 조건부 칸 합침이 들어 있습니다. 버튼을 누르면 새 버전 데이터가 바뀌어 다시 그려지고, 비교도 자동으로 다시 됩니다.

표마다 고유 ID 달기. 제목도 내용도 거의 같은 표가 반복되는데 가운데에 하나가 끼어든 경우입니다(새 버전의 2번째 표가 새로 생긴 것이고, 3번째 표는 함량만 99.4 → 99.7 로 바뀜). ID 가 없으면 모듈은 내용이 비슷한 정도로만 짝을 짓기 때문에, 끼어든 표를 "수정된 옛 표"로 보고 원래 있던 표를 "추가"로 표시합니다. 컴포넌트가 제목과 표를 한 묶음으로 감싸고 그 묶음에 data-sgc-key="실행ID" 를 달면 정확히 짝지어집니다 (표에만 달아도 표는 정확히 짝지어집니다). 아래 스위치로 바로 비교해 보세요.

어떻게 만든 화면이든 브라우저에 그려진 결과를 비교합니다. 아래는 일부러 다루기 어렵게 만든 화면입니다: 표로 짠 옛날식 레이아웃(font·center 태그), 화면 안에 다시 들어 있는 iframe(안쪽에서 따로 스크롤), 웹 컴포넌트, 입력칸 값. 변경 목록에서 iframe 안쪽 항목을 누르면 안쪽 스크롤까지 움직여 찾아갑니다.
